# ADR 0001: 通用命令执行层 —— 特例提升为通用,专用工具保留为语义壳

- 状态: 已接受 (Accepted)
- 日期: 2026-08-20

## 背景

windows-remote 最初按协议逐个提供工具(`adb` / `fastboot` / `uart_*`),其中 `fastboot_flash` 为解决「本地镜像须先送达远程 PC」内嵌了「SCP 传输 → sha256 双端校验 → 执行」三段式。观察发现一切远程命令本质上只有两类:不带附件的普通命令(`adb logcat`),和带附件的命令(`fastboot flash boot boot.img`)。三段式作为特例已被验证,但被锁死在单一工具内,多附件命令流(`fastboot flash a a.img && fastboot flash b b.img`)、脚本+镜像组合(`python flash_all.py`)均无法一次表达。

## 决策

1. 将三段式提升为**通用执行层**,新增 `run_command(command, attachments)` 作为统一入口。
2. **两阶段原子**:全部附件传输+校验通过后命令才执行,任一失败整体中止——杜绝「boot 刷了新版、dtbo 还是旧版」的混版状态。
3. **完整性校验焊死在 server 内**,不暴露 upload / verify / run 三原语给调用方(AI)编排——校验后才能执行是安全不变量,调用方只能触发、不能绕过。
4. **附件缓存采用「原文件名 + 内容指纹清单」**,指纹一致跳过传输,内容变化自动失效;不做内容寻址存储(多版本共存对刷机场景无价值)。
5. **专用工具保留,改为通用层的薄壳**:`adb` 的防挂起 / `-tt` PTY、`uart_*` 的文件通道等协议语义由专用工具继续承载,通用工具不吸收。
6. 多命令(`&&` / `||`)自动经 `cmd /s /c` 执行(远程默认 shell 为 PowerShell 5.1,不支持这两个操作符);单命令不包装,存量行为零变化。
7. 超时后终止 SSH 会话,并按命令特征清理远程残留进程(匹配须排除清理进程自身)。

## 被拒绝的备选

- **通用工具吸收一切、废弃专用工具**:丢失协议特有语义修正,调用方必须自行记住防挂起等约定,必然踩坑。
- **暴露 upload / verify / run 原语**:灵活但允许跳过校验直接执行,安全不变量失守。
- **内容寻址存储(按 hash 命名附件)**:多版本共存对「永远只刷最新」的调试工作流无价值,徒增链接/拷贝复杂度。
- **CLI 同步出 `rmt-run`**:MCP 是主使用路径,CLI 后续按需再补(本次明确不做)。

## 后果

- 新增协议(如 qfil)零接口改动,直接走通用入口。
- `adb_push` / `fastboot_flash` 自动获得缓存命中跳传,重复刷同一镜像零传输等待。
- `exec_command` / `adb` / `fastboot` 等存量工具的超时路径仅终止本地 SSH 会话,远程残留清理暂未接入(可后续推广,需注意主动杀进程会改变存量工具行为)。
