# 案例 95916:开关机 5000 次进 recovery 界面出现一次

- 项目/平台:MT5825(bengal_515,LA.VENDOR 13.2.1 + QSSI 14.0.R1,BOOT.XF.4.1)
- 证据:jpp_20260728.txt(886M 串口,5004 轮,票面板)+ 0812 复测(串口+logcat 403 轮)

## 最终结论(三事件结构)

核心缺陷 = 快速开关机下偶发 boot 早期静默卡死 + 2 次 PMIC GPIO 变种;
recovery 界面 = RescueParty mitigationCount 累计至 L5 的下游表现。

- 逐级链:L1-L3 静默(588s/240s/255s 轮)→ L4#1(轮 A,GPIO 链实证,143.9s)
  → 4h 轮降级清零 → L1-L3 重攒 → L4#2(轮 B,同 GPIO 链,138.1s)
  → L4#3(轮 C 静默卡死 1797.8s)→ L5(轮 D,371.9s 'recovery' → ABL Recovery:1
  → recovery UI 停 2.6h = 票面)
- 0812 复测:同核心缺陷复现(1/403);recovery 为用户空间路径(内核未重启,
  ABL Recovery:0,拉起路径未定谳)

## 定案关键信号

1. reboot command 全量统计:4999 空 + 3×'RescueParty' + 1×'recovery'
2. `could not increase module refcount` 全文 10 次,精确圈定 2 个 GPIO 异常轮
3. pm7250b@2 兄弟驱动齐挂(spmi-gpio -22 / adc-tm5 -517×3 / usb-pdphy -517×4)
4. 自愈判据:轮 A/B 的 'RescueParty' 后下一轮均 `command ''`
5. 4h 轮(14346s)= count 降级清零点,解释轮 B 重新从低级起步

## 被证伪的假说(最有价值的部分)

| 假说 | 证伪证据 |
|------|----------|
| 测试主机 ADB 拉起 recovery(v1) | collect_log.bat 全文仅 wait-for-device+logcat |
| 人工 adb 触发(v2) | USB CONNECTED→UI 1.77s < 枚举完成 6.5s,通道未建立 |
| 「composer 无崩溃证据」 | 漏扫 apexd 点名路径——init/apexd 双路径必须都扫 |
| 「SF 存活=显示栈正常」 | SF 进程在跑但 IComposer/SurfaceFlingerAIDL 接口缺失 |
| recovery 分区损坏 | 4096Bytes 是读首块固定打印;异常轮 Load Image 276ms 完整加载 |

## 修复方向

压测版关 RescueParty(切断放大器)> PMIC probe 健壮性 + msm_drm -517 重试策略
> persist logcat 落盘复测(events log 抓 rescue_note count≥2)
