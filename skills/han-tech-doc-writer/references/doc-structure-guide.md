# 技术文档结构指南

定义 5 种文档类型的推荐结构模板。Step 2 根据文档类型选择对应模板生成大纲。

## 1. 架构文档 (Architecture Doc)

适用场景：系统架构说明、模块设计文档、组件关系梳理

推荐结构：
1. **概述** (~10%)
   - 背景与目标
   - 系统定位
   - 核心需求/约束
2. **整体架构** (~25%)
   - 📊 系统架构图 (system-architecture)
   - 分层说明
   - 技术选型
3. **核心模块设计** (~35%)
   - 📊 模块关系图 (system-architecture)
   - 每个模块：职责、接口、依赖、关键数据结构
4. **关键流程** (~20%)
   - 📊 核心流程图 (flowchart) 或时序图 (sequence-diagram)
   - 数据流/控制流描述
5. **部署方案** (~10%，可选)
   - 📊 部署架构图 (network-topology)
6. **总结与展望** (~5%)

### 信息图机会

- **Hero**: 系统概念全景图，放在概述前（文档第一屏）
- **核心模块**: 模块能力全景图，放在 3. 核心模块设计 开头
- 注: 信息图数量建议 1-2 张（hero + 1 个关键位置），避免信息过载

## 2. API/接口文档 (API Doc)

适用场景：函数接口说明、REST API 文档、RPC 接口定义

推荐结构：
1. **概述** (~10%)
   - 接口用途与适用范围
2. **接口定义** (~40%)
   - 函数原型 / Endpoint
   - 参数说明（推荐表格形式）
   - 返回值与错误码
3. **调用流程** (~25%)
   - 📊 时序图 (sequence-diagram)
   - 典型调用场景
4. **示例代码** (~15%)
   - 至少一个可运行的示例
5. **注意事项** (~10%)
   - 线程安全、重入性、性能考虑

### 信息图机会

- **Hero**（可选）: API 全景概览（端点地图/接口分组）
- 注: API 文档偏重精确接口定义，信息图优先级最低，仅在源内容足够丰富时使用

## 3. 排障指南 (Troubleshooting Guide)

适用场景：问题排查文档、故障诊断手册、调试指南

推荐结构：
1. **问题现象** (~15%)
   - 症状描述
   - 触发条件
2. **环境信息** (~10%)
   - 软件版本、硬件平台、配置
3. **排查流程** (~35%)
   - 📊 排查流程图 (flowchart，决策树形式)
   - 每步：检查项 + 判断条件 + 分支
4. **根因分析** (~25%)
   - 📊 根因时序图 (sequence-diagram) 或因果链图 (flowchart)
   - 调用栈/日志分析
5. **解决方案** (~10%)
   - 修复步骤或 workaround
6. **验证步骤** (~5%)
   - 如何确认问题已解决

### 信息图机会

- **Hero**: 排查全景图（问题域→排查路径→根因→修复），放在概述前
- 注: 排查决策树用 D2 flowchart，信息图仅做"问题域总览"

## 4. 设计文档 (Design Doc)

适用场景：方案设计、技术方案评审、RFC

推荐结构：
1. **背景与动机** (~15%)
   - 为什么需要这个方案
   - 现有方案的不足
2. **方案对比** (~20%)
   - 候选方案及优劣
3. **详细设计** (~40%)
   - 📊 架构图 (system-architecture)
   - 📊 数据流图 (flowchart)
   - 关键数据结构/接口变更
4. **影响分析** (~15%)
   - 对现有系统的影响
   - 兼容性/迁移策略
5. **实施计划** (~10%)
   - 📊 甘特图 (gantt-chart，可选)
   - 里程碑与分工

### 信息图机会

- **Hero**: 方案全景图（背景→候选方案→选定方案→影响），放在背景前
- **对比矩阵**（可选）: 方案对比信息图，放在 2. 方案对比 处
- 注: 设计文档信息图机会最多，hero + 对比矩阵共 1-2 张

## 5. 知识库文章 (Knowledge Base Article)

适用场景：概念解释、最佳实践、操作指南、技术笔记

推荐结构：
1. **概念定义** (~15%)
   - 一句话定义 + 应用场景
2. **工作原理** (~35%)
   - 📊 架构图/流程图/状态图（根据内容选择）
   - 分层或分步骤解释
3. **最佳实践** (~25%)
   - 推荐用法
   - 常见反模式
4. **常见问题** (~15%)
   - FAQ 形式
5. **相关资源** (~10%)
   - 参考链接、延伸阅读

### 信息图机会

- **Hero**: 概念全景图（概念→原理→实践→FAQ），放在概述前
- 注: 知识库文章 hero 信息图效果好，建议 1 张

## 通用规则

- 每章至少一个配图机会
- D2 图表（📊）与信息图（🎨）互补：D2 展示精确技术细节，信息图展示概念全景
- 章节间逻辑递进：总→分→总
- 标题层级不跳级（h2 下直接 h3）
- 篇幅比例是指导，可根据内容灵活调整
