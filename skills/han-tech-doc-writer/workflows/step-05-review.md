# Step 5: 质量审核

输出前进行自查，确保 Obsidian 规范与文档质量。逐项检查，发现问题立即修复。

**对照** `references/obsidian-guide.md` §7 自检清单。

## 5.1 Obsidian 规范检查

- [ ] 文件名 = frontmatter `title` = 所有 `[[]]` 链接名
- [ ] frontmatter 含 `title` / `type` / `created` / `updated`
- [ ] `doc_type` / `source_type` 已填写
- [ ] 无 wikilink 带 `.md` 后缀（如 `[[page.md]]`）
- [ ] 无 kebab-case 文件名（如 `gpio-subsystem.md`）
- [ ] 核心概念在正文中有 `[[wikilink]]`
- [ ] 文末有「相关链接」章节（如有 wikilink）
- [ ] 无 `<div align="center">` / HTML `<details>` 折叠块

## 5.2 完整性检查

- [ ] 所有章节都已填写内容，无空白段落
- [ ] 没有 "TODO"、"待补充"、"TBD" 标记（有意标注的除外）
- [ ] 每个 D2 图表都有对应的文字说明
- [ ] 每个信息图都有对应的说明文字
- [ ] Step 2 计划的所有 D2 图表都已生成并嵌入
- [ ] Step 2 计划的所有信息图都已生成并嵌入（或标注缺失）
- [ ] Step 2 wikilink 清单中的链接已在正文出现

## 5.3 准确性检查

- [ ] 技术术语拼写正确（英文大小写、下划线、括号匹配）
- [ ] API/函数名与源文档一致
- [ ] D2 图表中的节点名、连接关系与实际一致
- [ ] 信息图中的概念与正文一致
- [ ] 数据/数字与源文档一致
- [ ] 没有凭空编造的内容

## 5.4 格式检查

- [ ] 标题层级正确（h1 → h2 → h3，不跳级）
- [ ] 代码块标注了正确的语言类型（```c、```python、```bash 等）
- [ ] D2 SVG 路径正确（`_diagrams/<slug>-<短码>.svg`）
- [ ] 信息图 PNG 路径正确（`_diagrams/<slug>-info.png`）
- [ ] 表格对齐整齐，表头语义化
- [ ] 列表项语法一致

## 5.5 D2 图表质量检查

- [ ] 每个图都有编号和标题（图 N: 标题）
- [ ] 图标题使用斜体：`*图 N: 标题*`
- [ ] 正文中有图引用（"如图 N 所示"）
- [ ] SVG 文件存在且非空（`ls -lh _diagrams/*.svg` 验证）
- [ ] 正文嵌入使用 `![[...svg]]` wikilink 语法
- [ ] 中文标签无乱码

## 5.6 信息图质量检查

- [ ] 信息图文件存在且非空
- [ ] 信息图在文档中显示正常（路径正确）
- [ ] 信息图位于醒目位置（文档开篇/章节开篇）
- [ ] 信息图内容与 D2 图表互补（不重复）
- [ ] 信息图中的中文清晰可读（无乱码、无截断）
- [ ] 信息图下方有引导性说明文字
- [ ] 信息图不使用图号，与 D2 图表编号体系独立

## 5.7 不通过处理

如果某项不通过：
- Obsidian 规范/格式/文本问题 → 直接修复
- D2 图片问题 → 回到 Step 3 重新编译 SVG
- 信息图问题 → 回到 Step 3.5 重新生成，或标注缺失后继续
- 内容准确性问题 → 回到 Step 4 修正
- 结构/完整性/wikilink 问题 → 回到 Step 2 调整大纲

**全部通过后，读取 `workflows/step-06-output.md` 继续。**
