# Step 4: 文档写作

将 Step 2 的大纲、Step 3 的 D2 图表和信息图组装成完整的中文技术文档。

## 4.1 准备工作

读取 `references/writing-style-guide.md`，确保写作符合中文技术写作规范。

## 4.2 写作流程

按大纲逐章写作。对每一章：

### a. 嵌入信息图（Hero/章节开篇）

信息图放在**醒目位置**，不同于 D2 图表的正文内嵌方式。

#### Hero 信息图（文档开篇）

放在文档标题与元信息之后、第一章之前：

```markdown
# [文档标题]

> 本文档由 han-tech-doc-writer 整理生成 | 日期: YYYY-MM-DD
> 原始来源: [来源描述]

<div align="center">

![文档概念全景](_diagrams/info-overview.png)

*文档核心概念全景 — 一图看懂 [主题]*

</div>

---

## 1. 概述
```

#### 章节开篇信息图

放在章节标题之后、正文之前：

```markdown
## 2. 核心模块设计

<div align="center">

![模块能力全景](_diagrams/info-modules.png)

*模块能力全景 — [模块数量] 大模块协作关系一览*

</div>

### 2.1 模块A

正文内容...
```

#### 信息图嵌入规则

- 信息图**不编 D2 式的图号**（图 1, 图 2...），也不与 D2 图混编
- 信息图使用 `<div align="center">` 包裹，全宽居中
- 信息图下方用斜体说明，句式为"X 全景/一图看懂 Y"
- 信息图后可选 1-2 句引导文字，然后进入正文
- 信息图与 D2 图表**互补而非重复**：信息图展示"是什么"的全景，D2 图展示"怎么运作"的细节

### b. 写正文

- 正文全中文，技术术语保留英文原词
- 首次出现的术语可加括号标注中文：`Direct Memory Access (DMA)`
- 函数/变量名用反引号：`class_create()`、`dwc3_remove`
- 段落长度 3-7 句
- 使用陈述句，避免主观判断词

### c. 嵌入 D2 图表

如果该章有对应的 D2 图表：

```markdown
![图 N: 标题名称](_diagrams/<name>.png)

*图 N: 标题名称*

上图展示了 [核心内容]，关键点在于：
- 要点一
- 要点二
```

规则：
- 图编号从 1 开始，D2 图表独立编号（不包含信息图）
- 正文必须先引用再放图："如图 N 所示，..."
- 图后紧跟 2-5 句解释
- 同时提供 SVG 链接（用 HTML details 折叠或单独标注）

### d. 代码块

源内容中的代码使用 fenced code block：
````markdown
```c
static int dwc3_remove(struct platform_device *pdev)
{
    ...
}
```
````

## 4.3 特殊情况处理

### 图片目录不存在或编译失败

如果 Step 3 未成功生成图片（d2 未安装或编译失败），将 D2 源代码作为代码块嵌入：

```markdown
**图 N: 标题名称** (D2 源代码，安装 d2 后编译)

```d2
... D2 源码 ...
```
```

### 信息图缺失

如果某章有信息图需求但未能生成，在原位置标注:
> 🎨 *信息图: [主题] — 未能生成，可后续通过"加个信息图"命令补充*

### 源内容不足

如果源内容对某章的信息不够，不要编造。标注 `[待补充]` 或从常识补充后用注释标注"本节内容基于通用知识，非源文档直接提供"。

## 4.4 文档头尾

### 文档头部

```markdown
# [文档标题]

> 本文档由 han-tech-doc-writer 整理生成 | 日期: YYYY-MM-DD
> 原始来源: [来源描述]

```

### 文档尾部

```markdown
---

*本文档由 han-tech-doc-writer 自动生成，如需调整请告知。*
```
