# 分析案例：宏芯宇 HBN1901280CHBC 128G 高低温挂测数据损坏（2026-08-15）

- **日期**: 2026-08-15
- **性质**: 离线根因分析（禅道 BUG 96455，无设备实测）
- **器件**: 宏芯宇 HBN1901280CHBC 128G（UFS，挂 1d84000.ufshc；测试口径误称 "EMMC"）
- **平台**: MC5616 / Qualcomm parrot (SM6450) / Android 15 / kernel 5.10.236-qki
- **条件**: 高温 60 °C + 低温 20 °C 挂测（dd 类读写循环 + 每轮 MD5 校验），48 h
- **现象**: 只跑约 60 轮（正常节律 40 s/轮，理论 4000+）；两块板 3/3 全复现；新问题

## 异常指纹（截图证据，第 58 轮）

| 指纹 | 数值 | 正常值 | 解读 |
|------|------|--------|------|
| 读耗时 | 4,127,200 ms（68.8 min） | ~32 s | 器件内部反复重试，读阻塞 |
| 读速率 | 0.0254 MB/s | 26-33 MB/s | 同上 |
| MD5 校验 | old cd573cfa… ≠ new 6f7448de… | 一致 | **数据面持久性损坏（最硬证据）** |
| 下一轮写速 | 731.7 MB/s | 140-230 MB/s | 假写速=控制器假完成，数据未落盘 |

## 轮次-时长算术（次数骤降的判定法）

48 h ÷ ~60 轮 ≈ 48 分钟/轮 ≈ 单次读卡死（~69 min）+ 正常读写（~40 s）。
对得上 → "每轮被小时级卡死拖慢"；对不上 → 脚本中断/重启。

## 根因结论（proposed）

高温应力下 UFS 颗粒读不可纠正错误/坏块蔓延 → 数据损坏 + 小时级读阻塞。
两板 3/3 + 上版不存在 → 指向本批次来料/器件可靠性，非软件回归。
注意：同颗粒在 96242 案件（板温 42 °C、无 MD5 校验）曾判"不支持器件故障"——
温度域与校验强度不同，结论不可外推。

## 待闭环验证

1. 换已知良好颗粒同条件复测（判据：≥4000 轮、无 fail 行、单轮 read < 60 s）
2. 复测抓串口 log：ufshcd_abort / UIC error / ECC 打印
3. 同颗粒常温对照：区分"高温恶化"与"颗粒缺陷"
4. MD5 值 + 板温记录提交宏芯宇 RMA

## 沉淀要点

- MD5 old≠new + 假写速（超物理带宽）+ 小时级读阻塞，三者同现 → 器件数据损坏，可基本排除软件
- "EMMC 挂测"叫法 ≠ 器件是 eMMC，以 dtsi/实际节点（1d84000.ufshc）为准
- 器件历史"健康"结论只在同温度域 + 同校验强度下可外推
