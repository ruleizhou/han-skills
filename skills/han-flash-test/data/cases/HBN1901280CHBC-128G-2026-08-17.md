# Case: 宏芯宇 HBN1901280CHBC 128G UFS — 高低温挂测中断 + 数据校验失败(96455)

- 日期: 2026-08-17
- 平台: MC5616(parrot/SM6450,kernel 5.10.236-qki-consolidate,Android 15)
- 器件: 宏芯宇 HBN1901280CHBC 128G UFS(票面口语"EMMC")
- 环境: 高温 60° / 低温 20° 挂测 48H,概率 3/3,两块单板均异常
- 结论: 器件数据通路 0 错误,挂测中断根因是系统 boot 不完成瘫死(显示 ESD/audio/zygote),"数据损坏"最大嫌疑为 page cache 未落盘假象

## 现象

- 挂测 48H 只跑 ~60 轮(预期数百轮)
- 第 58 次读 4127200ms(0.025 MB/s,正常 29~34 MB/s)后 MD5 校验 fail(err 2)
- 第 59 次写 731 MB/s(超 UFS 物理极限 → 纯 page cache 佐证)

## 内核侧证据(115123 行 MobaXterm 串口 log,GB18030 转码)

| 签名 | 数量 |
|------|------|
| msm-dsi-error(ESD/PANEL_DEAD) | 60726(53%) |
| [sda] Synchronizing SCSI cache(UFS runtime PM 震荡) | 6579 |
| sysrq Show Blocked State(末段 4.2s/次) | 627 |
| F2FS recover(非干净重启) | 1240 |
| mmc / I/O error / panic / tombstone / OOM | **全 0** |

时间轴:13 次 `reboot 'shell'` 有序循环(~105s/轮)→ 最终 boot 31.7s 起 DSI ESD
持续失败 → 192.5s audio-hal 4-times-exit → 534.9s zygote 4-times-exit →
boot 永不完成,瘫 16.8h(uptime 60532s)。

## 方法论沉淀

1. **MobaXterm log 文件头是 scrollback 回放**,真实抓取从 header 行之后开始;
   时间戳与行号不单调时先修 log 结构再分析
2. **单 boot 段的"异常"必须对比全部 boot 段基线**:SCM call failed / ICC
   register failed / user_dtbo 加载失败在该工程机 15 次 boot 全有,是噪音基线,
   不能当根因(本次两次险些误判)
3. **写速 > 物理极限 = page cache 佐证**:挂测工具不 fsync + warm reset →
   MD5 fail 不等于器件数据损坏
4. **UFS 在 kernel 侧无 mmc 签名**:UFS 走 scsi(sd 0:0:0:x 多 LUN),
   mmc 类 grep 命中 0 是正常形态,要按 scsi/ufshcd 词汇搜

## 建议

- 挂测判定器件责任前必须改直写块设备(fio --direct=1 / dd oflag=direct + fsync)
- 复测时 loglevel 提到 7 抓 INFO 级 task dump(本次 sysrq 627 次却无栈可看)
- 串口 log 之外补 logcat -b all 与 dmesg 落盘
